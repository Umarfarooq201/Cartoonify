# GC-PROD: Summary of the Three Empirical Privacy Attacks

Prepared: 1 November 2026. Scope: the original full-day Attack 1, unrestricted-observation Attack 2, and final constrained-null geographic-placement case studies. This is an explanatory document, not a new experiment or a replacement for frozen manifests.

## 1. Overview

| Aspect | Attack 1: Longitudinal record linkage | Attack 2: Relative home inference | Attack 3: Geographic placement |
| --- | --- | --- | --- |
| Question | Can a later daily trace be linked to a reference pseudonym? | Can the stored relative home location be approximated from repeated observations? | Can relative mobility geometry help rank the user's absolute city? |
| Mobility input | Evaluation-day queries and selected reference days | All reference observations, including daytime and nighttime | Frozen recurring clusters extracted from the reference observations |
| Inference population | 33 reference candidates for each of 2,284 queries | 33 users | All 33 users in each candidate-set configuration |
| Evaluation population | 2,282 valid queries | All 33 users for success rates | Five evaluable labelled users per configuration |
| Candidate universe | 33 pseudonymous users | Observed relative coordinates in the selected cluster | 37 cities per configuration |
| Auxiliary geographic data | None | None | GHSL, ESA WorldCover, and GHS-WUP polygons |
| Main method | Minimum eligible binned day-pair distance | Weighted DBSCAN and centroid-nearest observed point | Rigid-placement search and constrained-null normalization |
| Main clean result | Top-1 62.09% | Error <=50 m for 75.76% | Predefined: Top-1 1/5; seeded: Top-1 0/25 cases |
| What success does not establish | A person's real-world identity | An absolute residential address | A worldwide unique location or posterior probability |

The reported metric distances use the metre convention recorded in the project configurations and scoring manifests. This review did not independently calibrate the relative coordinates against original GPS.

## 3. Attack 1: Longitudinal Record Linkage

### Objective and input

Link an evaluation-day trajectory to one of the **33 reference pseudonyms**. This is closed-set, hashed-to-hashed identification across different periods, not raw-GPS matching or recovery of real-world identity.

The matcher uses timestamps and relative coordinates. Reference pseudonyms identify candidates; query identifiers identify trajectory groups. Home coordinates, distance-from-home fields, home flags, and true query-user labels are not matching features.

### Frozen procedure

1. Divide each calendar day into **96 bins of 15 minutes**, covering the full day.
2. If a bin contains multiple observations, retain the observation closest to its centre, with earliest timestamp resolving time-offset ties.
3. Keep reference days with at least **12 populated bins**.
4. Sort each user's eligible reference dates and select **24 approximately evenly spaced days** using `np.rint(np.linspace(0, n_days - 1, 24)).astype(int)`.
5. Compare a query and reference day only if they have at least **12 common populated bins**.
6. Calculate their mean spatial distance over those common bins.
7. Assign each candidate user the **minimum eligible day-pair distance** across that user's 24 selected days.
8. Rank candidates by increasing score, resolving equal scores by lexicographic candidate identifier. Non-finite scores follow finite scores.

For ordinary Euclidean scoring:

\[
d(q,r)=\frac{1}{|B(q,r)|}\sum_{b\in B(q,r)}\|x_{q,b}-x_{r,b}\|_2,
\qquad |B(q,r)|\ge12,
\]

\[
s(q,u)=\min_{r\in R_u:\,|B(q,r)|\ge12}d(q,r).
\]

The secondary toroidal variant uses `min(abs(a-b), 25000-abs(a-b))` for each coordinate-axis difference before calculating Euclidean distance. It does not change the candidate cohort or temporal protocol.

| Valid queries scored | 2,282 | 2,282 |
| Invalid queries excluded | 2 | 2 |
| Candidates per query | 33 | 33 |

| Top-1 | 62.09% | 63.01% |

These are **pooled valid-query metrics**, not equally weighted user-macro averages. Random-ranking baselines for 33 candidates are Top-1 **3.03%**, Top-3 **9.09%**, and Top-5 **15.15%**.

The two queries with fewer than 12 populated bins remain identifiable as invalid outputs but are excluded from accuracy and rank summaries; they are not failures silently added to the denominator.

Original query identifiers contain user-derived bookkeeping prefixes. The matcher treats the entire identifier only as a grouping key. The saved `TEST/manifest.json` records a passed diagnostic with randomized query identifiers. The prior diagnostic comparison found unchanged scores, rankings, overlap/validity decisions, and metrics. This summary did not rerun that diagnostic.

**Conclusion:** the tested relative trajectories remain substantially linkable across periods. This establishes association with reference pseudonyms, not identification of named people or a general population-level success rate.

## 4. Attack 2: Relative Home Inference

### Objective and input

Predict a home-associated coordinate **within the relative map**, using all available frozen reference observations for each of the **33 users**.

This is one unrestricted-observation experiment: **daytime and nighttime observations are used together**. A separate nighttime-only implementation exists historically, but it is not the Attack 2 definition summarized here.

The inference loader reads only `customer_id` and `coordinate`. It does not load timestamps, stored home coordinates, distance-from-home values, or home flags.

### Frozen procedure

1. Collapse duplicate relative coordinates into unique points, weighted by original observation counts.
2. Apply deterministic weighted DBSCAN with **eps=100 m**, **min_samples=20**, and ordinary Euclidean distance.
3. Select the non-noise cluster with the highest total observation count; resolve equal cluster sizes by cluster identifier.
4. Calculate its observation-weighted centroid.
5. Predict the observed cluster point nearest to that centroid. The implementation uses a fixed numerical tie comparison and lexicographic point ordering.
6. Score predictions separately against the stored clean relative home coordinate using ordinary Euclidean error.

This is a centroid-nearest observed-point estimator, not a claim that the exact mathematical medoid is calculated. No time-of-day restriction or toroidal clustering is applied.

### Clean results

| Metric | Result |
| --- | ---: |
| Evaluated users / valid predictions | 33 / 33 |
| Exact coordinate match | 4/33 = 12.12% |
| Error <=25 m | 22/33 = 66.67% |
| Error <=50 m | 25/33 = 75.76% |
| Error <=100 m | 26/33 = 78.79% |
| Mean error | 1,532.96 m |
| Median error | 11.00 m |
| 90th-percentile error | 7,402.59 m |

Threshold success means **error <= threshold**, not strictly less than the threshold. Success-rate denominators include all 33 users; distance summaries in conditions with failed predictions use valid predictions only.

The original scoring JSON directly records the exact-match, <=50 m, <=100 m, and distance summaries. The <=25 m result above is also reported in the thesis; this document does not recompute per-user errors.

**Conclusion:** repeated relative observations can support inference of a home-associated location, judged against the stored relative home reference. This is not independent verification of a residential address. The large errors do not establish that the selected clusters were workplaces or commute locations; that would require additional evidence.

## 5. Attack 3: Geographic Placement / City Inference

### Objective, population, and candidate sets

Rank candidate cities by compatibility with recurring relative mobility geometry and public geographic features. The attack scores **all 33 users**, not only users with known city labels.

The thesis reports:

- One **predefined 37-city case study**.
- **Five seeded 37-city robustness configurations**, each with the same seven fixed candidates and 30 deterministically sampled distractors.
- Seeds **101, 202, 303, 404, 505**, corresponding to Seed 01 through Seed 05.
- Fixed candidates: Darmstadt, Leipzig, Frankfurt, Würzburg, Trier, Monastir, and Berlin.
- The same city set is applied to every user within a configuration. Distractors may overlap across seeds.

The frozen seeded design samples distractors by sorting eligible candidates on `SHA-256(namespace|seed|candidate_id)`, breaking ties by candidate ID, and taking the first 30. Candidate sampling does not use user-level labels, identities, or previous rankings.

There are **six externally mapped users**, but one mapped location, **Breithardt**, is outside the candidate sets. Closed-set city accuracy therefore uses **five evaluable users per configuration**. The excluded location is not silently counted as an incorrect closed-set prediction. The predefined case study is **not a sixth random seed**.

### Mobility and public-data inputs

- Recurring clusters originate from the same reference period used by the other attacks.
- Step 3 retains clusters meeting at least three distinct days and three visits, using DBSCAN eps=100 m and min_samples=20; at most five dominant clusters are selected per user.
- The Step 3 manifest records **162 selected clusters across 33 users**.
- The multiseed worker input is `selected_clusters_analysis_ids.csv`, using internal analysis IDs rather than customer IDs. The external identity/city mapping remains separate.

| Public input | Recorded product |
| --- | --- |
| Candidate-city polygons | GHS-WUP-MTUC R2025A V1.1 |
| Total built-up surface | GHS-BUILT-S, R2023A, epoch 2020, 100 m |
| Non-residential built-up surface | GHS-BUILT-S NRES, R2023A, epoch 2020, 100 m |
| Population grid | GHS-POP, R2023A, epoch 2020, 100 m |
| Land cover | ESA WorldCover 2021 v200, 10 m |

Public maps contain absolute geographic information; the unavailable information is the users' original absolute GPS trajectories. The population raster is not automatically a population-density product merely because it supplies population-related features.

### Placement and constrained-null scoring

1. Place each frozen relative cluster configuration over translation anchors on a **250 m grid** within the candidate polygon.
2. Search **72 rotations at 5-degree intervals** and **both reflection states**. Do not scale inter-cluster geometry.
3. Evaluate the frozen geographic feature compatibility. The translation anchor must be inside the polygon; other clusters may lie in the buffered map extent, so this is not a requirement that every cluster be inside the city boundary.
4. Apply the same raster-coverage and land-validity rules to actual and null placements. Cluster centres in permanent water, snow/ice, or herbaceous wetland classes are excluded.
5. Aggregate valid placement scores using **log-mean-exp**, not the maximum placement alone or a selected Top-K placement subset.
6. Generate angular nulls preserving anchor-relative distances, cluster weights, and radii. Keep the anchor fixed; accept a proposal only if it has valid placements. Seek **nine accepted null configurations**, with at most **90 deterministic proposal attempts**.
7. Use the primary median-difference score:

\[
S_{\mathrm{valid\_norm}}=S_{\mathrm{actual\_valid}}-
\operatorname{median}(S_{\mathrm{valid\_nulls}}).
\]

8. Rank cities by decreasing normalized score, breaking ties by candidate ID. A secondary null z-score is also saved; do not silently substitute its rankings for the primary median-normalized rankings.

If actual placements are all invalid, or fewer than nine valid nulls are obtained within 90 attempts, the pair is marked impossible with score `-inf` and processing continues. Therefore, saying that every completed pair necessarily has nine valid nulls would be incorrect. The predefined constrained-null result manifest records **19 impossible pairs out of 1,221**.

## 6. Relationship to T5/T6

Attacks 1 and 2 were also evaluated on noisy and generalized reference coordinates in separate result directories. Those are sensitivity experiments, not additional attack definitions.

- Noise: wrapped planar Laplace perturbation at epsilon 0.2, 0.02, and 0.001; Attack 1 queries stay clean and Attack 2 clean home references stay scoring-only.
- Generalization: replace trajectory coordinates by cell centres for 250, 500, and 1000-unit grids, retaining the attack protocols.
- Result directories: `results/noise/record_linkage/seed_2/`, `results/noise/home_inference/seed_2/`, `results/generalization/record_linkage/`, and `results/generalization/home_inference/`.
- The final Attack 2 presentation uses unrestricted observations, not a separate nighttime-only series.
- No noisy/generalized Attack 3 result is asserted by this summary.
- Prediction utility uses a separate inherited 13-user pipeline. It is not an individual-level paired comparison with the 33-user privacy cohort.

## 7. Corrections to the Supplied LLM Summary

1. Attack 3 inference uses **all 33 users**; five users are evaluable for geographic accuracy.
2. The predefined case study contributes **five cases**, separately from the **25 seeded cases**.
3. Do not identify large-error home clusters as work or commute without evidence.
4. The home-inference threshold is **inclusive**; it is not automatically identical to the prediction label's strict home-radius rule.
5. Do not claim an evaluated uniform-random home-guessing baseline: a domain and sampling model would first need specification.
6. Do not call city inference real-world identity recovery or claim a particular global coordinate projection without checking the relevant execution path.
7. Replace traffic-light claims such as “high vulnerability” or “empirical resistance” with the actual measured outcomes and their scope.
8. Keep median-normalized and z-score city rankings distinct, and distinguish actual ranking artifacts from externally evaluated true-city metrics.
